# 四套主题配色 · 方案 C

四套配色来自 `docs/palettes.zip` 里的 `DESIGN.md`（C1 藕粉雾蓝 / C2 樱花奶油 / C3 薄荷奶霜 / C4 蜜桃乌龙）。
落地方式只有一句话：**只换颜色，不换骨架**。四套共用同一份组件规则、同一套字号与间距阶梯、同一组语义色，
以及同一组圆角（22 / 18 / 14 / 11，四套完全一致），所以切换配色不会让任何一个盒子挪位。

- 取值：`appearance` 为 `flat` / `editorial` / `playful` / `c1` / `c2` / `c3` / `c4`，写在 `settings.json` 里；
- 界面上：面板右上角「界面风格设置」→「主题配色 · 方案 C」四个色卡，或「设置 → 待办任务 → 界面风格」；
- 样式上：`.td-seat[data-todo-appearance="c1…c4"]` 覆盖 token，没有一条组件规则是配色专属的。

## 1. 为什么是这些值，而不是原型里的品牌原色

原型为了让「一眼看到配色性格」，按钮直接用品牌原色；四套里有两套的白字**不达 AA**：

| 主题 | 原型品牌色配白字 | 落地（text-safe） | 实测 |
| --- | --- | --- | --- |
| C1 藕粉雾蓝 | `#7C74E8` 3.80 ✗ | `#5F55D8` | 5.56 ✓ |
| C2 樱花奶油 | `#E8618C` 3.22 ✗ | `#BE4470` | 4.94 ✓ |
| C3 薄荷奶霜 | `#2FA98C` 2.93 ✗ | `#1F7A64` | 5.22 ✓ |
| C4 蜜桃乌龙 | `#F2865E` 2.52 ✗ | `#B2552F` | 4.96 ✓ |

所以：**白字只出现在上表的 `brand-cta` 上**（`--td-accent` / `--td-accent-on:#fff`）；
品牌原色只做 `--td-brand`（图标、清单色兜底），点缀色在插件里不承担文字角色；
语义色（成功 `#17795C`、提醒 `#8E5A0B`、错误 `#B23A55`、信息 `#6C63E0`）四套恒定，换肤不改状态含义。

三级文字（`--td-text-3`）取的是 ink-2 与 ink-3 的混合值，而不是 DESIGN 里的 ink-3：ink-3 在 12px 以下只有 3.1:1，
而面板里 `.td-sub`、`.td-countbadge` 这类小字用的正是这一档，混合后表内实测 4.5–5.1:1。

DESIGN.md 里的 `accent`（樱粉 / 杏 / 薄荷杏 / 雾紫）在插件里没有「点缀色文字」的位置，
它的浅底 `accent-soft` 与 `accent-line` 也没有对应的语义块 —— 这两组值只保留在本文档里备查，
不参与 token 映射；需要点缀色时请先**新增一个有语义的用法**，而不是顺手把 `--td-accent` 指过去。

## 3. 深色模式

四套配色没有第二套深色设计稿：`body[data-ds-dark-theme]` 下表面、线条与文字全部交回宿主 token
（`--dsw-alias-bg-base` / `bg-layer-1` / `label-primary` / `label-secondary`，well 仍由 layer-1 向 canvas 混合），
只把强调色换成该主题的 `brand-3`，并让 `--td-accent-on` 变成该主题的墨色 ——
即「浅色填充 + 墨色字」，四套实测 5.0–7.4:1：

| 主题 | 深色 `--td-accent` | `--td-accent-on` |
| --- | --- | --- |
| C1 | `#A99BFF` | `#2C2440` |
| C2 | `#FF9DB8` | `#3A2530` |
| C3 | `#71D2B9` | `#1F3A33` |
| C4 | `#FFB394` | `#3B2A23` |

## 4. 验收

`npm test` 里的 `verify-client-render.mjs` 逐套断言：token 存在且为 text-safe 值、四套圆角阶梯一致、
深色映射存在、色卡预览类存在；`audit-css.mjs` 断言配色块是唯一的字面色来源（其余组件规则必须读 token）。
新增或调整配色时，请同时更新这三处断言与上表，别让文档先跑。
