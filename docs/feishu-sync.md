# 同步到飞书多维表格（Bitable）

这份文档讲一件事：把 dsh-task-todo 里的任务——**包括每个状态**——镜像到一张飞书多维表格，
并在飞书里当看板用。

- 插件侧零依赖：用的是运行时自带的 `fetch`，没有新增 npm 依赖。
- 默认**不启用**：设置里打开「启用」并填好凭证之前，插件不会发起任何网络请求。
- 匹配是按 `任务ID` 字段做的，所以**重复执行是幂等的**：没变的任务一行都不会重写。

## 1. 飞书侧准备

1. 打开 [飞书开放平台](https://open.feishu.cn/app)，创建**企业自建应用**。
2. 在「凭证与基础信息」里拿到 **App ID** 与 **App Secret**。
3. 在「权限管理」里开通多维表格读写权限：`bitable:app`（如需读取表格元数据再加 `bitable:app:readonly`）。
4. 发布/启用该应用版本（企业内自建应用需管理员通过）。
5. 在目标多维表格右上角「···」→「添加文档应用」，把这个应用加为**协作者**（可编辑）。
   没加协作者时，接口会返回 `NOTEXIST` / 权限类错误，看起来像「表不存在」。

## 2. 取出 app_token 与 table_id

打开目标多维表格，看浏览器地址栏：

```
https://<租户>.feishu.cn/base/bascnXXXXXXXXXXXX?table=tblYYYYYYYYYYYY&view=vew...
                              ^^^^^^^^^^^^^^^^^^        ^^^^^^^^^^^^^^^^^^
                              app_token                 table_id
```

- `app_token`：`/base/` 之后、`?` 之前的那段。
- `table_id`：`table=` 之后、`&` 之前的那段。

Lark 国际版把接口域名设为 `https://open.larksuite.com`（设置里的 `baseUrl`）。

## 3. 建表字段

在这张数据表里建好下列**文本**字段（列名要与本表一致；不想用文本类型的字段可以改类型，
但文本最省事，因为插件按字符串写值）。`任务ID` 是匹配用的钥匙，**必须有**。

| 列名 | 内容 | 示例 |
| --- | --- | --- |
| `任务ID` | 任务 id（**匹配键**，可在设置里改名） | `t_m3k9x2` |
| `标题` | 任务标题 | 交季度报告 |
| `状态` | 未完成 / 今天到期 / 已逾期 / 已完成 | 今天到期 |
| `完成` | 是 / 否 | 否 |
| `逾期` | 是 / 否 | 是 |
| `清单` | 所属清单名 | 工作 |
| `优先级` | 无 / 低 / 中 / 高 | 高 |
| `截止时间` | `YYYY-MM-DD` 或 `YYYY-MM-DDTHH:mm`，空为未安排 | 2026-09-20 |
| `开始时间` | 同上 | 2026-09-18 |
| `标签` | 逗号分隔 | 重要, 报告 |
| `父任务` | 父任务标题，顶层任务留空 | 交季度报告 |
| `子任务进度` | 已完成/总数 | 1/2 |
| `重复` | 重复规则的自然语言描述 | 每周 周五 |
| `备注` | 任务备注（可多行） | 先拉数据 |
| `创建时间` / `更新时间` | 任务的时间戳 | 2026-09-17T08:00:00.000Z |

> 想只看某类任务，就在飞书里对 `状态` / `逾期` / `清单` 建视图或分组——这正是把它们同步出来的意义。

## 4. 插件设置

设置 → 待办任务 → **飞书同步**：

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 启用 | 关 | 总开关；未启用时 `/todo sync` 会拒绝并提示 |
| appId | 空 | 自建应用 App ID |
| appSecret | 空 | 自建应用 App Secret（只写在本机 `<DSH_HOME>/todo/settings.json`，保存后不再回显） |
| appToken | 空 | 多维表格 app_token |
| tableId | 空 | 数据表 table_id |
| baseUrl | `https://open.feishu.cn` | 国际版填 `https://open.larksuite.com` |
| 自动同步 | 关 | 任务变动后自动推一次（防抖 3 秒） |
| 同步子任务 | 开 | 关闭则只同步顶层任务 |
| 含已完成 | 开 | 关闭则已完成任务不写入远端 |
| 删除远端行 | 开 | 本地删除的任务，同时删除远端对应行 |
| keyField | `任务ID` | 匹配用的列名 |

设置值落在 **`<DSH_HOME>/todo/settings.json`**（普通 JSON，可手动编辑 / 备份）。无界面环境
（例如 `dsh headless`）也可以配：在那个文件里写 `{"feishu": {"enabled": true, "appId": "…"}}`，
或者给 profile 的 `cordis.patch.yml` 里 `todo` 条目加一个 `config:` 块（作为种子层，settings.json
优先）。改完重启宿主即可。

## 5. 同步语义

- **匹配**：按 `keyField`（默认 `任务ID`）列的值与任务的 `id` 对应。
- **幂等**：先读远端全部行做 diff，只对**真正有差异**的字段发 `batch_update`；
  没变的任务不产生任何写请求。因此连续同步两次，第二次是 0 写。
- **删除**：只有带 `任务ID` 且有对应本地任务的行才会被管理；远端那些**不带 `任务ID`** 的行
  （别人手写的）永远不删。「删除远端行」关闭时，本地删除只保留远端历史。
- **拒绝而非复制**：远端表里已有数据、但**没有一行**带 `keyField` 时，同步会直接报错，
  而不是给每个任务新建一行。报错信息会告诉你表里有几行、缺哪个字段。
- **dry run**：`/todo sync 预览`（或工具 `dryRun: true`）只做读 + diff，返回将要
  新增 / 更新 / 删除的数量，不写任何东西。
- **批量**：每次最多 500 行（飞书上限），超出会自动分批。

## 6. 怎么触发

| 方式 | 用法 |
| --- | --- |
| 设置页 | 设置 → 待办任务 → 「预览同步」/「立即同步」（先保存再执行） |
| Agent 工具 | `task_sync_feishu`：`action=status`（不联网）/ `action=sync`（可 `dryRun`、`prune`） |
| 斜杠命令 | `/todo sync`、`/todo sync 状态`、`/todo sync 预览` |
| HTTP（界面/脚本） | `POST /todo/api/syncFeishu`、`POST /todo/api/feishuStatus` |
| 自动 | 设置里打开「自动同步」后，任何任务改动会在 3 秒静默期后自动推一次 |

## 7. 状态与排错

`/todo sync 状态` 会打印：是否启用、目标、匹配字段、上次同步时间与结果。

常见错误：

| 报错 | 原因 |
| --- | --- |
| `飞书同步未启用：…` | 设置里没打开「启用」 |
| `飞书同步缺少配置：feishu.appId、…` | 四个必填项有空的 |
| `飞书接口错误 code=99991663：app_id or app_secret invalid` | App ID / Secret 不对，或应用未发布 |
| `飞书接口错误 code=1254005：…NOTEXIST…` | `appToken` / `tableId` 不对，或应用没被加为表格协作者 |
| `飞书接口错误 code=1254xxx：FieldNameNotFound` | 表里缺列，对照第 3 节补上 |
| `远端表格有 N 行，但没有一行带「任务ID」字段` | 表里没有匹配列（或列名不同，改设置里的 `keyField`） |
| `飞书接口请求失败：…` | 网络 / 代理问题；`baseUrl` 是否写对 |

## 8. 安全

- `appSecret` 只写在本机 `<DSH_HOME>/todo/settings.json`，插件的状态接口**不会**把它返回给
  界面或模型（`feishuStatus()` 脱敏，设置页也只回一个「已保存」标记）。
- 建议给自建应用只开多维表格相关权限，并只在需要的表格上添加协作者。
- 同步是**单向**的（DSH → 飞书）：飞书里手改的行，下次同步会被本地状态覆盖；
  不带 `任务ID` 的手写行不受影响。
