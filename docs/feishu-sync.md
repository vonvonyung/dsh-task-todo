# 同步到飞书多维表格（Bitable）

这份文档讲一件事：把 dsh-task-todo 里的任务——**包括每个状态**——镜像到一张飞书多维表格，
并在飞书里当看板用。

- 插件侧零依赖：用的是运行时自带的 `fetch`，没有新增 npm 依赖。
- 默认**不启用**：设置里打开「启用」并填好凭证之前，插件不会发起任何网络请求。
- 匹配是按 `任务ID` 字段做的，所以**重复执行是幂等的**：没变的任务一行都不会重写。

## 1. 飞书侧准备

1. 打开 [飞书开放平台](https://open.feishu.cn/app)，创建**企业自建应用**。
2. 在「凭证与基础信息」里拿到 **App ID** 与 **App Secret**。
3. 在「权限管理」里开通多维表格读写权限：`bitable:app`（如需读取表格元数据再加 `bitable:app:readonly`）。
4. 发布/启用该应用版本（企业内自建应用需管理员通过）。
5. 在目标多维表格右上角「···」→「添加文档应用」，把这个应用加为**协作者**（可编辑）。
   没加协作者时，接口会返回 `NOTEXIST` / 权限类错误，看起来像「表不存在」。

## 2. 取出 app_token 与 table_id

打开目标多维表格，看浏览器地址栏：

```
https://<租户>.feishu.cn/base/bascnXXXXXXXXXXXX?table=tblYYYYYYYYYYYY&view=vew...
                              ^^^^^^^^^^^^^^^^^^        ^^^^^^^^^^^^^^^^^^
                              app_token                 table_id
```

- `app_token`：`/base/` 之后、`?` 之前的那段。
- `table_id`：`table=` 之后、`&` 之前的那段。

Lark 国际版把接口域名设为 `https://open.larksuite.com`（设置里的 `baseUrl`）。

## 3. 建表字段

在这张数据表里建好下列**文本**字段（列名要与本表一致；不想用文本类型的字段可以改类型，
但文本最省事，因为插件按字符串写值）。`任务ID` 是匹配用的钥匙，**必须有**。

| 列名 | 内容 | 示例 |
| --- | --- | --- |
| `任务ID` | 任务 id（**匹配键**，可在设置里改名） | `t_m3k9x2` |
| `标题` | 任务标题 | 交季度报告 |
| `状态` | 未完成 / 今天到期 / 已逾期 / 已完成 | 今天到期 |
| `完成` | 是 / 否 | 否 |
| `逾期` | 是 / 否 | 是 |
| `清单` | 所属清单名 | 工作 |
| `优先级` | 无 / 低 / 中 / 高 | 高 |
| `截止时间` | `YYYY-MM-DD` 或 `YYYY-MM-DDTHH:mm`，空为未安排 | 2026-09-20 |
| `开始时间` | 同上 | 2026-09-18 |
| `标签` | 逗号分隔 | 重要, 报告 |
| `父任务` | 父任务标题，顶层任务留空 | 交季度报告 |
| `子任务进度` | 已完成/总数 | 1/2 |
| `重复` | 重复规则的自然语言描述 | 每周 周五 |
| `备注` | 任务备注（可多行） | 先拉数据 |
| `完成记录` | 按时间追加的完成情况历史；空总结显示为“未填写” | 2026-09-17 08:00｜材料已提交 |
| `关联跟进` | 本行的来源任务或该任务创建的跟进任务（含 ID、状态、截止日） | 跟进任务：核对审批（t_…；未完成；截止 2026-10-17） |
| `创建时间` / `更新时间` | 任务的时间戳 | 2026-09-17T08:00:00.000Z |

> 想只看某类任务，就在飞书里对 `状态` / `逾期` / `清单` 建视图或分组——这正是把它们同步出来的意义。

## 4. 插件设置

设置 → 待办任务 → **飞书同步**：

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 启用 | 关 | 总开关；未启用时 `/todo sync` 会拒绝并提示 |
| appId | 空 | 自建应用 App ID |
| appSecret | 空 | 自建应用 App Secret（只写在本机 `<DSH_HOME>/todo/settings.json`，保存后不再回显） |
| appToken | 空 | 多维表格 app_token |
| tableId | 空 | 数据表 table_id |
| baseUrl | `https://open.feishu.cn` | 国际版填 `https://open.larksuite.com` |
| 自动同步 | 关 | 任务变动后自动推一次（防抖 3 秒）；冲突任务跳过并报告，不覆盖飞书修改 |
| 同步子任务 | 开 | 关闭则只同步顶层任务 |
| 含已完成 | 开 | 关闭则已完成任务不写入远端 |
| 删除远端行 | **关** | 默认关。开启后也只删除「本地删过、有删除记录」的行；远端其它行永不删除 |
| keyField | `任务ID` | 匹配用的列名 |

设置值落在 **`<DSH_HOME>/todo/settings.json`**（普通 JSON，可手动编辑 / 备份）。无界面环境
（例如 `dsh headless`）也可以配：在那个文件里写 `{"feishu": {"enabled": true, "appId": "…"}}`，
或者给 profile 的 `cordis.patch.yml` 里 `todo` 条目加一个 `config:` 块（作为种子层，settings.json
优先）。改完重启宿主即可。

## 5. 同步语义

- **匹配**：按 `keyField`（默认 `任务ID`）列的值与任务的 `id` 对应。
- **幂等**：先读远端全部行做 diff，只对**真正有差异**的字段发 `batch_update`；
  没变的任务不产生任何写请求。因此连续同步两次，第二次是 0 写。
- **同步只新增与更新，默认什么都不删**。远端多出来的行（别人写的、别的机器写的、或你手加的）
  一个都不会被动；报告里会写「远端另有 N 行不属于本工作区，保持原样」。
- **要删，必须同时满足两件事**：设置里打开「删除远端行」**并且**该行对应的任务在本地**确实被删过**
  （插件会记一条删除记录 / tombstone）。两个条件缺一不可 ——
  因为「远端这行的 key 本地没有」既可能是你删了它，也可能是别人加进来的，单凭这一点删就是误删。
  只有带 `任务ID` 的行才会被这样处理；**不带 `任务ID`** 的手写行永远不动。
  删除前还会和最近一次共同基准比对：远端行被改过、出现未跟踪的非空列、存在重复任务 ID，或没有共同基准时，删除会作为冲突停止/跳过，不会静默删掉飞书修改。行安全删掉后删除记录随即清除，所以同 key 的行以后再加回来不会被连带删除。
- **拒绝而非复制**：远端表里已有数据、但**没有一行**带 `keyField` 时，同步会直接报错，
  而不是给每个任务新建一行。报错信息会告诉你表里有几行、缺哪个字段。
- **共同基准与冲突保护**：每次成功同步后，插件在本地任务文件里保存按字段计算的共同状态指纹（不保存原始表格标识或重复的字段明文）。同步不会用 `更新时间` 猜哪边较新。
  如果某个本地更新或删除会覆盖/移除自共同基准以来的飞书修改，默认策略是停止写入并展示本地值、飞书值及冲突方向；用户可选「按本地覆盖飞书」「按飞书更新本地」或「跳过冲突」。从旧表格首次开始同步、没有共同基准的差异也会要求显式选择。
- **确认快照**：预览携带快照确认令牌。设置页确认前会检查本地、远端及对账基准是否仍与预览一致；任一项变化就拒绝应用并要求重做预览。
- **自动同步**：自动同步无法提问，所以冲突任务会跳过，其他无冲突任务继续同步。远端发生变化或没有共同基准的本地删除也会跳过，飞书行不会被删；冲突详情进入宿主日志和「上次同步」状态，不会静默覆盖。
- **dry run**：`/todo sync 预览`（或工具 `dryRun: true`）只做读 + diff，返回将要新增 / 更新 / 删除的数量，不写任何东西。
- **批量**：每次最多 500 行（飞书上限），超出会自动分批。

## 6. 怎么触发

| 方式 | 用法 |
| --- | --- |
| 设置页 | 设置 → 待办任务 → 「测试连接」「补全字段」「预览同步」「立即同步」「完整对账」「从飞书更新本地（预览）」「从飞书补洞（预览）」「从飞书补洞」 |
| Agent 工具 | `task_sync_feishu`：`action=status`（不联网）/ `test` / `fields` / `reconcile` / `pull` / `applyRemote` / `sync`（可 `dryRun`、`prune`、`conflictPolicy`；反向确认传 `previewToken`） |
| 斜杠命令 | `/todo sync`、`/todo sync 状态\|测试\|字段\|对账\|更新本地预览\|确认更新本地\|补洞[预览]\|预览\|按本地覆盖\|跳过冲突` |
| HTTP（界面/脚本） | `POST /todo/api/feishuStatus` / `feishuTest` / `feishuFields` / `feishuReconcile` / `feishuPull` / `feishuApplyRemote` / `syncFeishu` |
| 自动 | 设置里打开「自动同步」后，任何任务改动会在 3 秒静默期后自动推一次 |

### 同步动作分别在什么时候用

| 动作 | 写什么 | 什么时候点 |
| --- | --- | --- |
| **测试连接** | 什么都不写（一次 token + 读字段 + 读一页行） | 填完凭证先点它。失败会原样给出飞书的 `code` / `message`，并指出卡在哪一步（凭证 / 读字段 / 读行） |
| **补全字段** | 只往表里**加**缺的列，全部建成「文本」；已有列不删不改 | 刚建好多维表格、还是空表的时候 —— 省得手工敲十几个列名还敲错 |
| **预览同步** | 什么都不写；若有冲突，显示本地值 / 飞书值及原因 | 写入前核对差异 |
| **立即同步** | 无冲突时本地 → 飞书；有冲突时先停下，要求选择方向 | 日常推送。选「按本地覆盖飞书」才会明确覆盖冲突字段；「跳过冲突」只同步安全项 |
| **完整对账** | 什么都不写 | 怀疑两边不一致时。逐行比出：完全一致 / 有差异（列出字段、本地值、飞书值与方向）/ 本地有远端没有 / 远端有本地没有 |
| **从飞书更新本地（预览）** | 什么都不写，列出匹配任务的可还原差异 | 先检查将写入本地的字段；随后点「确认应用以上预览」 |
| **从飞书补洞（预览）** | 什么都不写 | 动手之前看看会补进来哪些任务 |
| **从飞书补洞** | 只往本地**新增**远端有、本地没有的行 | 换机器、清过数据，或别人往表里加了内容之后 |

**反向动作分开处理**：

### 「从飞书补洞」只新增

- 只看远端**有 key、本地没有这个 id**的行；本地已有的任务绝不覆盖或删除。
- 远端 `任务ID` 成为新任务 id，确保下次同步更新原行而非复制。
- 会还原标题、备注、完成布尔值、清单、优先级、标签、截止 / 开始时间、创建时间；父任务仅在本地能按标题唯一找到时关联。
- 重复规则、完成历史、跟进关系，以及 `状态` / `逾期` / `子任务进度` 等派生字段不猜测恢复，会在报告中注明。
- 远端清单本地不存在时会顺带创建清单；导入静默执行，不会反过来触发自动同步。

### 「从飞书更新本地」先预览、再确认

- 只处理**本地已存在且远端任务 ID 唯一匹配**的任务；远端独有行仍由「补洞」负责。
- 可还原字段为标题、备注、完成布尔值、清单、优先级、截止 / 开始日期、标签，以及可唯一解析且不会形成循环的父任务。
- `完成` 只改本地 `done` 布尔值；不调用普通完成流程，不造 `completedAt` / 完成记录，不推进重复任务或重置子任务。
- `状态` / `逾期` / `子任务进度` 是派生字段；`重复`、`完成记录`、`关联跟进` 是不能安全反推的摘要；`创建时间` 是既有任务的历史时间戳，`更新时间` 是本地时间的镜像。它们只报告、不导入。（「补洞」创建新任务时仍可读取远端创建时间。）
- 远端响应里缺失的单元格不会按空值处理，以免清空本地内容。非法日期 / 优先级、重复 ID、无法唯一解析的父任务会跳过并说明原因。
- 设置页确认仅适用于展示的那份预览；确认前如果本地或飞书任一侧变化，会提示重新预览，不会应用过期值。

## 7. 状态与排错

`/todo sync 状态` 会打印：是否启用、目标、匹配字段、上次同步时间与结果。

常见错误：

| 报错 | 原因 |
| --- | --- |
| `飞书同步未启用：…` | 设置里没打开「启用」。`sync`、`pull` 与 `applyRemote` 需要它；`test` / `fields` / `reconcile` 不需要（它们本来就是启用前的准备与诊断） |
| `飞书同步缺少配置：feishu.appId、…` | 四个必填项有空的 |
| `飞书接口错误 code=99991663：app_id or app_secret invalid` | App ID / Secret 不对，或应用未发布 |
| `飞书接口错误 code=1254005：…NOTEXIST…` | `appToken` / `tableId` 不对，或应用没被加为表格协作者 |
| `飞书接口错误 code=1254xxx：FieldNameNotFound` | 表里缺列 —— 点「补全字段」即可 |
| `飞书接口错误 code=1254006：field name … already exists` | 补全字段时的同名冲突（少见；报告里会指出是哪一列） |
| `远端表格有 N 行，但没有一行带「任务ID」字段` | 表里没有匹配列（或列名不同，改设置里的 `keyField`） |
| `飞书接口请求失败：…` | 网络 / 代理问题；`baseUrl` 是否写对 |

对账报「处处有差异」时，先看它打印的缺列清单：缺一列会让那一列在每一行上都算差异。

## 8. 安全

- `appSecret` 只写在本机 `<DSH_HOME>/todo/settings.json`，插件的状态接口**不会**把它返回给
  界面或模型（`feishuStatus()` 脱敏，设置页也只回一个「已保存」标记）。
- 建议给自建应用只开多维表格相关权限，并只在需要的表格上添加协作者。
- 普通同步保护飞书侧修改：有共同基准且飞书字段已变时，不会默认覆盖；冲突必须显式选择方向。未带 `任务ID` 的手写行始终不受同步和删除影响。
- 反向更新会本地静默写入，不会触发自动回写；基准字段只保存 SHA-256 指纹，表格标识也以哈希存储。
